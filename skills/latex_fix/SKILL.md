# 修复规则

1. **只做必要修改**：修报错、补缺失的宏包/环境/文件引用，不要改动正文内容与结论。
2. 常见错误与对策：
   - `Undefined control sequence` → 补 `\usepackage{...}`，或改用 TeX Live 自带宏包的等价命令。
   - `File 'xxx.png' not found` → 改成实际存在的图片路径（图片在 `figures/` 下，注意相对路径是 `../figures/`）。
   - `Missing $ inserted` / `Runaway argument` → 检查数学环境与花括号配对，中文与公式混排要放在数学环境内。
   - 中文字体问题 → 用 `\documentclass{ctexart}`，不要手工指定字体文件。
   - 表格/图片浮动体报错 → 检查 `tabular` 列数与 `&` 数量是否一致。
3. **禁止**为了编译通过而删除实质内容（图表、公式、章节）；实在无法编译的复杂排版，可降级为等价的可编译写法。
4. 保留原有的 `\label` / `\ref` / `\cite` 一致性。

# 输出格式（必须严格遵守）

**只输出补丁 JSON 数组，不要输出整个文件。**
论文有数万字符，整篇重发会超出单次输出上限而被截断（实测约 1.45 万 token 就到头），
一旦截断，你的修复会被判定为无效并被回滚。

[
  {"find": "原文件里逐字存在、且唯一的片段", "replace": "替换后的内容", "why": "修的是哪个错"}
]

规则：

- `find` 必须是原文件里**逐字存在且唯一**的片段，尽量短（一两行即可），**不要**写行号、不要改写原文标点。
- 只写需要改的地方：改 3 处就给 3 个补丁，改 1 处就给 1 个。
- `replace` 是替换后的文本；留空字符串表示删除该片段。
- 若某处必须整段重写，就把**整段**作为 `find`，重写后的整段作为 `replace`。
- 不要输出解释文字；JSON 之外不要写别的内容（用代码围栏包住也可以，程序能容错）。
- 修图片路径时，只能改成「真实存在的图片文件」一节中列出的确切路径；
  用不上的图直接删掉对应的 `\includegraphics`（连同它的 `figure` 环境），
  **不要保留不存在的路径，也不要编造新文件名**。
