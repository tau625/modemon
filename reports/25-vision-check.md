# 排版视觉自动校验（vision 自检）

> 按蓝方 `tools/tikz_vision_check.py` / `tools/data_fig_vision_check.py` 的
> **恢复规格原文**实现。本文件记录实现要点、实测校准过程、以及它抓出的真缺陷。

---

## 1. 核心设计：vision 是「加分项」不是「硬门槛」

这是原文 docstring 完整记载的工程教训，也是本模块最重要的约束：

> ⛔ 旧逻辑是「首行非纯 PASS 即 FAIL」，配合提示词里的主观项（大片空白 / 是否美观），
>    几何图永远被挑出至少一条 → **每张烧满 2 轮重编**，是「画完卡很久」的 vision 侧根因。

因此判决口径是**只认结构化标记**：

```python
ISSUE_RE = re.compile(r"(?mi)^\s*ISSUE\s*\d*\s*[:：]")

def verdict(reply: str) -> int:
    if not reply or not reply.strip():   return 0   # 空 → 放行
    if ISSUE_RE.search(reply):           return 1   # 结构化问题 → 判失败
    return 0                                        # 泛泛评论/无法解析 → 放行
```

`tests/test_vision_check.py` 用 19 条用例把这条口径锁死（含「泛泛肯定必须放行」
与「讲解格式本身不得误判」两类边界）。

## 2. 退出码契约（对齐原文）

```
0 = 通过（PASS）
1 = 有问题（输出具体问题描述）
2 = API 不可用（未配置 key 或调用失败）
```

## 3. 其它按原文实现的细节

| 项 | 值 |
|---|---|
| 图片体积阈值 | `_MAX_IMG_BYTES = 3_500_000`（base64 放大约 33%，原图留 3.5MB） |
| 超限处理 | PIL 等比压缩；PIL 缺失或失败则**回退原图** |
| 读不出 | 返回 `None`，调用方**跳过**（不阻塞） |
| 凭据优先级 | `EDITOR_AI_API_KEY`+`EDITOR_AI_BASE_URL` → 回退 `OPENAI_API_KEY`+`OPENAI_BASE_URL` |
| TikZ 检查项 | 7 项，逐字取自原文 |

## 4. 两个后端

| 后端 | 用途 | 可用条件 |
|---|---|---|
| `OpenAIBackend` | 直连 OpenAI 兼容 vision API（蓝方原方案） | 配置了凭据 |
| `AgentVisionBackend` | **用 Claude Code 自己看图** | 只要 agent 可用 |

第二个是必要的补充：agent 的 `Read` 工具能看图（实测它会 `Read page-1.png` 并据此修图），
于是没有外部 vision 凭据的环境也能跑视觉自检。

## 5. 实测校准：两个只有真跑才发现的坑

### 坑一：提示词写成临时文件 → agent 读不到

最初的 `_ask_via_agent` 把检查清单写进 `tempfile` 目录再让 agent 读。结果：

```
我无法读取问题文件：C:\...\Temp\vision-xxx\ask.txt
超出了本次会话允许的工作目录（E:\...\reports\assets），Read 和 shell 读取均被权限拦截
```

于是 agent **从来没拿到检查清单和 `ISSUE n:` 格式要求**，只能给泛泛评论，
而按判决口径泛泛评论放行 → **什么都查不出来**。

**修复**：提示词**内联**到 `-p` 参数，不写临时文件。

### 坑二：模型看不见图时会一律回答 PASS

必须做**视觉能力标定**：先用一张写有 `42` 的图问「图里写的是什么数字」，
答不上来就认定视觉不可用，报 `skipped` 而不是 `pass`。

不做这一步，模型看不了图就会凭提示词文字回答 PASS ——
**虚假信心比不检查更糟**。实测标定结论是本机模型**能**看图（读出了 42），
但这个防御必须在。

## 6. 它抓出的真缺陷

反向测试（中文变方框的图）**精准命中**：

```
[ISSUE] backend=agent
   ISSUE 1: 图表标题 中文字符全部显示为方框（tofu），无法阅读
   ISSUE 2: y轴轴标题 中文字符显示为方框（tofu），无法阅读
   ISSUE 3: x轴刻度标签 三处标签的中文部分均显示为方框，仅保留"+10%"可见
退出码: 1
```

对论文整页检查时又抓出 8 条我之前没发现的问题，其中 3 条已修复：

| # | 缺陷 | 处理 |
|---|---|---|
| 1 | **图题是 "scenarios"** —— 缺图注时我编造了个英文名 | ✅ 改为显式告警：「图 X **缺少图注**…请补充中文图注」 |
| 2 | **表题在表格下方** —— 中文规范是**表题在上、图题在下** | ✅ 已改 |
| 3 | 表头 `耗时 _s` —— 未登记列原样输出后下划线被转义 | ✅ 改为「下划线转空格」+ 补齐常用列标签 |
| 4 | **交叉引用错位**：正文写「见表 1/表 2」，实际表号是表 2/表 3 | ⏳ 待修（正文应使用 `\ref` 而非硬编码编号） |
| 5 | 页眉与内容不符：页眉「7 灵敏度分析」，页面是图表/参考文献 | ⏳ 待修 |
| 6 | 表题字重不一致（表2加粗 / 表3常规） | ⏳ 待修 |
| 7 | 参考文献编号应为 `[1][2][3]` 而非上标小数字 | ⏳ 待修 |
| 8 | 页面大块空白（第 1/3/4 页下部） | ⏳ 待修（与正文长短有关） |

> **第 1 条尤其值得记**：缺图注时编造一个像模像样的英文名（"scenarios"），
> 比留白更糟——它**掩盖了缺失**。现在改为显式告警。

## 8. 结论

视觉自检的价值在**抓"编译成功但内容不对"**这一类问题——
这正是单元测试与编译退出码覆盖不到的盲区。
本轮它抓出的 8 条问题里，有 3 条是我在写报告时才意识到的。

而它的**代价控制**同样重要：按原文的「非阻塞 + 只认结构化标记」口径，
不会因为几何图的主观评价而陷入无限重编。
